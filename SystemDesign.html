A. Product & System Overview

System Purpose: A modern, production-grade Inventory Management, Point of Sale (POS), Procurement, and Sales Management software application engineered specifically for a single retail shop in Saudi Arabia.

🇸🇦 Location & VAT

Saudi Arabia (KSA). Strict 15% VAT calculation (inclusive/exclusive) and ZATCA Phase 1 & 2 e-invoicing readiness.

👥 2 Fixed Roles

Manager (full administrative & financial authority) and Sales Executive (cashier & counter sales).

🌐 English UI for Staff

100% English navigation with simple terminology and intuitive icons for Bangladeshi expatriate retail staff.

Core Priority Hierarchy: Data Correctness > Financial Precision (DECIMAL 15,4) > Inventory Ledger Integrity > Local LAN Offline Resilience > Security > Speed.

E. Two-Database & Disaster Recovery Strategy

Guiding Principle: LIVE DATA ≠ BACKUP DATA. The live database must never block sales due to a backup operation or internet outage.

Database 1: Primary Live DB

  • Local PostgreSQL 16+ instance.
  • Single source of truth for real-time transactions.
  • Row-level locking (SELECT ... FOR UPDATE) for atomic stock consumption.
  • Write-Ahead Logging (WAL) for instant power outage crash recovery.

Database 2: Secondary Recovery DB

  • Standby PostgreSQL instance in sandbox container.
  • Used for periodic automated restore testing of dumps.
  • Ensures backups are physically restorable before a disaster occurs.
  • Warm failover target if primary disk experiences partial sector loss.

Automated Backup Lifecycle & Cloud Sync

  • Daily Snapshots: Automated at 01:00 AM AST; retained for 14 days.
  • Weekly Archives: Automated on Friday nights; retained for 8 weeks.
  • Monthly Archives: Automated on the 1st of each month; retained for 12 months.
  • AES-256-GCM Encryption: Dumps are encrypted locally before archival and accompanied by a SHA-256 checksum.
  • Non-blocking Cloud Upload: Transmits encrypted snapshots to Cloudflare R2 / AWS S3 when internet is online; queues safely when offline.

I. Saudi VAT & ZATCA E-Invoicing

Tax Exclusive (Standard)

Tax = Quantity * (Unit_Price * 0.15)

Total = (Quantity * Unit_Price) + Tax

Tax Inclusive

Base_Price = Unit_Price / 1.15

Tax = Quantity * (Unit_Price - Base_Price)

ZATCA TLV Base64 Generator (TypeScript)

export function generateZatcaTLVQR(
  sellerName: string,
  vatNumber: string,
  timestampIso: string,
  invoiceTotal: string,
  vatTotal: string
): string {
  const getTLVBuffer = (tag: number, value: string): Buffer => {
    const valueBuffer = Buffer.from(value, 'utf8');
    return Buffer.concat([Buffer.from([tag]), Buffer.from([valueBuffer.length]), valueBuffer]);
  };

  const tlvParts = [
    getTLVBuffer(1, sellerName),
    getTLVBuffer(2, vatNumber),
    getTLVBuffer(3, timestampIso),
    getTLVBuffer(4, invoiceTotal),
    getTLVBuffer(5, vatTotal),
  ];

  return Buffer.concat(tlvParts).toString('base64');
}

J. Inventory Stock Ledger & Weighted Average Costing

Stock levels are dynamically computed or cached directly from immutable stock ledger entries:

SELECT SUM(quantity) as current_stock 
FROM stock_movements 
WHERE product_id = ?;

WAC Formula (Executed upon receiving PO):

New_WAC = ((Current_Stock * Current_WAC) + (Received_Qty * Received_Unit_Cost)) / (Current_Stock + Received_Qty)

O. Product Images Architecture & POS Serving Strategy

High-quality product images are efficiently processed via Sharp, stored on the host filesystem (`./data/uploads/products/`), and served with long-term HTTP caching to ensure the POS catalog grid renders instantaneously across LAN terminals.

Image Upload & Processing Pipeline

graph TD Upload[Upload via Multi-part POST] --> Validate[Validate: <= 5MB, JPG/PNG/WebP] Validate --> Resize[Sharp Main: 800x800 Max] Validate --> Thumb[Sharp Thumb: 200x200 Square] Resize --> Save[Save to ./data/uploads/products/id/] Thumb --> Save Save --> DB[Insert record in product_images] DB --> Serve[Served via Nginx /uploads/ with 30-Day Cache]

POS Fast Image Query & Fallback Mechanism

  • Atomic Fetch: POS catalog query executes a fast LEFT JOIN to retrieve the primary thumbnail: SELECT p.id, p.name, p.selling_price, p.current_stock, img.file_path FROM products p LEFT JOIN product_images img ON img.product_id = p.id AND img.is_primary = TRUE WHERE p.is_active = TRUE;
  • Offline LAN Caching: All product image assets are served with Cache-Control: public, max-age=2592000, immutable. Browser caches images locally on counter PCs, eliminating network load during busy cashier shifts.
  • Graceful Fallback: If a product has no image uploaded or a network glitch occurs, the POS UI renders a stylized vector icon (Lucide Package/Cart) with high-contrast text.

    user_id INT REFERENCES users(id),
    type VARCHAR(50) NOT NULL,
    title VARCHAR(255) NOT NULL,
    message TEXT NOT NULL,
    severity VARCHAR(20) NOT NULL DEFAULT 'info',
    is_read BOOLEAN NOT NULL DEFAULT FALSE,
    reference_type VARCHAR(50),
    reference_id INT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
